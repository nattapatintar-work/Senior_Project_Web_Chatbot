**Stack decisions worth remembering:**

- **Flask over FastAPI.** Simpler for a first webhook, and `line-bot-sdk`'s documented
  examples are Flask-based, so less translation work.
- **Dictionary + fuzzy matching over a trained NER model** (`Claude.md:133`). Training
  NER would need thousands of labelled sentences — 3–4 weeks — to handle a 20-word
  vocabulary. Not a defensible trade.
- **Templates over LLM for reply text** (`Claude.md:175`). The LINE reply token expires
  in 10–30s; a 3–8s LLM round trip risks losing the reply entirely.

### `data/ingredients.json` — the central dictionary

20 ingredients, `yolo_class_id` 0–19 in the order agreed with Person 1. Schema follows
`Claude.md:355-363` exactly: `name_th`, `yolo_class_id`, `synonyms`.

This file is the join key between all three subsystems. CV outputs class IDs, NLP
outputs Thai words, the recommender needs canonical English keys — this dictionary is
the only thing that makes those the same vocabulary. `Claude.md:364` calls it the single
most common failure point in a project like this.

### `tests/test_contract.py` — 19 tests

Contract tests check **shape**, not correctness (`Claude.md:372`) — which is exactly why
they are useful while the internals are still mocks. The mock *values* are meaningless;
the *shape* is the real agreement Person 1 codes against.

The two highest-value tests are not the shape checks:

- `test_yolo_class_ids_are_sequential_from_zero` — YOLO identifies classes by number.
  If the dictionary is ever renumbered after training, every prediction silently maps to
  the wrong ingredient, with nothing crashing to reveal it.
- `test_no_synonym_is_shared_by_two_ingredients` — if one Thai word mapped to two
  ingredients, which one wins would depend on dict ordering. Works on one machine, fails
  on another.

## 4. Issues Found and Fixed

**`UnicodeEncodeError` when printing Thai or emoji to the terminal.**

A Thai-locale Windows console defaults to the **cp874** codepage, which cannot represent
emoji — printing 🍳 raised `UnicodeEncodeError` and killed the script; Thai text printed
as mojibake.

Fixed with `sys.stdout.reconfigure(encoding="utf-8")` in the `__main__` block of all
three modules.

Worth keeping on record: this is a **terminal-display issue only**. The strings were
always valid and LINE is UTF-8 throughout, so the bot itself was never affected. It will
recur on any Thai-locale Windows machine — including Person 1's.
