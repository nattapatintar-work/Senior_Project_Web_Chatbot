## 4. Issues Found and Fixed

**1. Search-methodology gap: dismissing snippets instead of fetching pages.** Root cause
of jicama/shallot/celery's false "unreachable" status across 4 attempts — see §2 above.
Fixed as a permanent `Claude.md` Working Style rule (general to all future source-hunting,
not scoped to recipes), plus a `data/RECIPE_BATCH_STATUS.md` note to try lifestyle-blog
platforms, not just recipe-specific sites.

**2. `coconut` vs. `coconut_milk` main-ingredient conflation.** The research phase for 3
dessert dishes assumed "coconut" was a valid target ingredient without checking whether
the source used fresh coconut (YOLO-detectable) or only coconut milk/cream (seasoning-
flagged, not YOLO-detectable) — only caught by re-fetching at write time. Fixed as a
standing check in `data/RECIPE_BATCH_STATUS.md`.

**3. `tools/thaifcd.py get` doesn't auto-cache.** Every `get`-fetched record this session
(4 of them) needed a manual copy into `data/thaifcd_cache.json` — flagged twice as a real
tool gap but not fixed in the tool itself (out of this session's scope; a `search`-side
auto-cache exists, `get` doesn't mirror it).

**4. A same-day data-integrity bug (th_165), not decay.** See §2. Notable because the
user specifically asked whether this was longstanding vs. fresh — traced conclusively via
`git log -S` to a single originating commit, one day old, confirming it was a fetch-skip
at write time in an unrelated batch, not something that degraded over multiple edits.
