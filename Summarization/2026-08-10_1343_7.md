### `recommend()`'s real pipeline

1. Each recipe becomes a document: `main_ingredients` listed **twice**,
   `optional_ingredients` **once**, `seasonings` **never** — the repetition is how term
   frequency expresses "mains matter more" without inventing a separate weighting scheme
   on top of TF-IDF.
2. `TfidfVectorizer(analyzer=lambda doc: doc)` fits once at import time over all 40
   recipe documents (`_RECIPE_MATRIX`, module-level — same reasoning as `extract.py`'s
   Trie: rebuilding per call would waste time on the ~30s LINE reply-token path, C11).
3. Per call: seasonings are stripped from the user's own ingredient list; candidates are
   **filtered before scoring** — health tags are ANDed (every requested tag must be in
   `health_tags` and absent from `excluded_for`), and an excluded ingredient only drops a
   recipe via `main_ingredients` or `seasonings`, never `optional_ingredients`.
4. Surviving candidates are vectorised and scored with `cosine_similarity`; zero-score
   dishes are dropped, scores clamped to `[0.0, 1.0]` and rounded to 2dp (guards a real
   float-epsilon overflow — see §5), sorted descending, sliced to `top_k`.

Frozen contract honored and extended by one field: same `id`/`name_th`/`score`/`have`/
`missing`/`nutrition` keys (all six pinned by `tests/test_contract.py`, which now runs
against real logic for the first time), plus a new `health_tags` passthrough for Week 8.
`tests/test_contract.py`'s `issubset` check means the addition is safe — nothing asserts
an exact key set.

## 4. Issues Found and Fixed

**1. `cosine_similarity` can return a float-epsilon overflow above 1.0**
(`1.0000000000000002`), which would fail the `0.0 <= score <= 1.0` contract
(`tests/test_contract.py::test_score_is_a_number_between_zero_and_one`) — a real,
if rare, way for data-dependent floating-point noise to break a frozen contract that has
nothing to do with logic correctness. Fixed by clamping into `[0.0, 1.0]` before rounding
to 2dp. Not anticipated in the pre-session plan; found while implementing.

**2. Two test-writing mistakes caught before commit**, both fixture assumptions that
turned out false when checked directly instead of assumed:

- `test_health_tags_are_ANDed_not_ORed` originally assumed no recipe is tagged both
  `vegan` and `keto` — false (`th_036`, `th_037` are both), and the original assertion
  happened to pass anyway by coincidence (no vegan dish contains chicken regardless of the
  keto filter), which would have silently hidden a real OR-instead-of-AND bug. Rewritten
  to isolate the AND behaviour directly using `th_004` (vegan, not keto — potato is a
  starch staple, disqualified by `HEALTH_TAGS.md`'s rule 2 regardless of carb count).
- `test_excluded_for_is_respected_even_if_health_tags_were_mistagged` looped over every
  recipe using its own `excluded_for` as the query, including recipes with `excluded_for:
  []` — an empty filter applies no filter at all, so those cases "passed" without testing
  anything. Restricted to recipes with a non-empty `excluded_for`.

Both caught by running the suite and reading the failures, not by re-deriving the fixture
data more carefully up front — worth naming as the same discipline session 6's C4 finding
established: verify an assumption against the real data before writing a test around it.

**3. `recommend.py` needed its own `sys.path` insert to run standalone.** Importing
`from nlp.extract import load_ingredients` broke `python recommender/recommend.py` run
directly (worked fine under pytest and under `api/main.py`, both of which already fix
`sys.path` themselves). Added the same one-line insert `nlp/extract.py`'s test files and
`api/main.py` already use, so all three entry points work independently.
